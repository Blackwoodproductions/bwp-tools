# Cutover codes and messages

One row per code. The `blocked_on` values arrive on `cutover_plan` (and, for a blocked first detect, on `cutover_record.last_error` as `<code>: <detail>`). The exception messages arrive as a refused call (`CADE 409: …`) or on `cutover_record.last_error` after a stage fails. Match on the start of the text. Where the source documents no remedy, the row says to escalate to the migration lead; do not improvise one.

| Code / message starts with | Where it shows | Means | Do this |
|---|---|---|---|
| `seo_service_unreachable` | plan `blocked_on` | CADE could not reach seo-service; the detail carries the exception, e.g. `ConnectError: [Errno 111] Connection refused` | Call `seo_domain_facts(domain)`. If it answers, seo-service is up and only CADE's path to it failed: re-run `cutover_plan` in a few minutes. If it is also `seo-service unreachable`, seo-service is down. Either way, if it persists, escalate to the migration lead with both results |
| `bwp_domain_missing` | plan `blocked_on` | bwp has no live domain with this name (`bwp has no live domain named <domain>`) | Call `seo_domain_facts(domain)`: `seo-service 404` means no row by that exact name (check the spelling or a `www.` variant), and `409` means two live rows share the name. Escalate to the migration lead with which one it was |
| `domain_not_registered` | plan `blocked_on` | CADE has no domain row; detect creates it, then the operator saves the WordPress connection | Run `detect`, then have the operator save the site's WordPress connection |
| `platform_connection_missing` | plan `blocked_on` | No WordPress connection: `install cade-seo, create an application password and save the connection, then re-run detect` | Install cade-seo, create an application password, save the connection, re-run `detect` |
| `platform_profile_empty` | plan `blocked_on` | The connection's default profile has no WordPress author | Give the connection's default profile its WordPress author, then re-run `detect` |
| `cade_seo_missing` | plan `blocked_on` | The site declares no `supports[]` at all, e.g. `supports[] is missing bwp_meta, footer_links, legacy_listener, legacy_pages, legacy_redirects, link_tree, resource_posts` | cade-seo is not installed or is far too old; escalate to the migration lead |
| `cade_seo_too_old` | plan `blocked_on` | cade-seo declares `supports[]` but lacks a flag, e.g. `supports[] is missing link_tree` | Escalate to the migration lead (the flags named in the detail are what the site is missing) |
| `site_unhealthy` | plan `blocked_on`; on a first detect also `last_error` as `site_unhealthy: Media upload failed: 403` | The site cannot take a publish (the health check uploads a real test file); the detail is the health check's error | Escalate to the migration lead (no remedy is documented) |
| `legitscript_host` | plan `blocked_on` | `a legitscript host never carries partner links` | Not migratable; tell the user and stop |
| `resources_base_taken` | plan `blocked_on` | `the site already serves /resources/; pick another base` | Escalate to the migration lead (choosing another base is not something this skill can do) |
| `agentic_unconverted` | plan `blocked_on` | Agentic members are still on the legacy link-out pattern: `N Agentic member(s) still on the legacy link-out pattern; run seolocal-app's scripts/agentic-linkout-to-agenticid.ts first` | An admin runs `scripts/agentic-linkout-to-agenticid.ts` in seolocal-app first; then re-run `detect` |
| `agentic_no_content` | plan `blocked_on` | `no Agentic row holds content: every row links out, so nothing migrates` | Nothing to migrate; escalate to the migration lead (the customer-facing path is "Contact support") |
| `legacy_paths_redirected` | plan `blocked_on` | Old addresses are redirected by something other than WordPress, so cade-seo could not forward them once the placeholders go; the detail lists each path and where it goes | Delete those rules in the site's redirect plugin (e.g. "301 Redirects" → Manage Redirects), then re-run `detect` |
| `<domain> has no usable cutover record: run detect first` (`CutoverNotDetected`) | stage refused (409) | A later stage was asked for before `detect` recorded the bwp id and state | Run `detect` first |
| `CADE has no domain named <domain>: run detect first` (`CutoverDomainUnknown`) | stage refused (404) | CADE has no domain row; only `detect` registers one | Run `detect` first |
| `<domain> is at stage '<x>'; '<y>' must come first` (`CutoverOutOfOrder`) | stage refused (409) | The stage depends on one the record has not reached (or the site is rolled back) | Run the stage the message names, in runbook order |
| `<domain> is already running stage '<x>'; wait for it to end` (`CutoverStageRunning`) | stage refused (409) | Another stage is queued or running; a second would race it | Wait and poll `cutover_record`; a stage running over 15 min counts as stale and may be re-queued |
| `CutoverPremiumSeoRunning` (`<domain>: Premium SEO is still running. Switch it off …`) | `remove` refused (409) or `last_error` | Premium SEO is still active; its next cron or `checkfiles` ping would rebuild every page `remove` deletes | Switch it off in wp-admin → Plugins → Deactivate (wp-admin is fine), then re-run `remove` |
| `<domain>: N placeholder page(s) survived the delete` (`CutoverPlaceholdersRemain`) | `remove` last_error | A Premium SEO rebuild was in flight; a leftover placeholder answers 200 blank and shadows the forward for its address | Re-run `remove` (any state, safe to re-run) |
| `<domain> is not live for the crawler` (`CutoverSiteNotLive`) | `finish` refused / last_error | The homepage carries no footer marker, or the homepage or listener did not answer (statuses are in the message) | Dashboard **Reconnect**, wait for bwp `2/1`, re-run `finish` |
| `<domain>: N migrated post(s) still load images from imagehosting.space` (`CutoverImagesHotlinked`) | `finish` last_error | Posts still load images from the old image host after three attempts each; the message lists the first five as `keyword/<id>` / `supportingKeyword/<id>` | Re-run `finish` (it retries); if it repeats, escalate to the migration lead with the listed posts |
| `<domain>: N URL write(s) failed (W written, S skipped)` (`CutoverUrlWritesFailed`) | `finish` or `rollback` last_error | A URL write to bwp failed; the stage did not advance and its transaction rolled back | Re-run the same stage (each write is idempotent, so a retry redoes them all); if it repeats, escalate to the migration lead |
| `<domain>: Premium SEO is not running. Switch it back on …` (`CutoverNotRollbackable`) | `rollback` refused / last_error | Premium SEO is off; a site whose plugin files are gone has nothing to roll back to | Switch Premium SEO back on in wp-admin, then re-run `rollback`. If its plugin files are gone (state A), it cannot be rolled back |
